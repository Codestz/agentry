Markdown ↔ FLOW round-trip: coalesce marks & trim before computeVersion
confidence usefulness ★ 2 id p:01KVH8JDEE… created 2026-06-20

Two markdown↔FLOW round-trip gotchas the workbench's golden tests / version checks caught (both fixed):

(1) A ProseMirror→markdown serializer must coalesce adjacent same-mark text runs — markdown-it splits a single emphasis span across a soft break into multiple text nodes, and per-node delimiter wrapping double-delimits (*write contract* → *write** **contract*). A self-referential golden test will NOT catch this — only a literal fidelity assertion does.

(2) A writer recomputing computeVersion MUST .trim() the body first: FLOW's TaskFileStore.render writes \n\n${body}\n but stamps over the trimmed body. Hashing the padding mismatches the stamp → every fresh save false-rejects as stale.

Why it mattersSilent artifact corruption + false optimistic-concurrency rejections are invisible in code review — they only surface as a broken save loop. This is the ADR-004 ↔ ADR-006 normalization bridge.
